# Architecture détaillée

| Crate | Rôle |
|---|---|
| `scout-core` | Données et logique **pures**, testées (ni disque, ni réseau, ni egui ; `sqlx` seulement avec la feature `sqlx`, pour `#[derive(FromRow)]`). `analysis` + `analysis/stats` : prix du jour = médiane des prix min du jour (date locale) ; week-end vs semaine par **test de permutation** (exact ou Monte-Carlo à graine fixe), effet de marché avec **les jours comme unité** ; prix du jour anormal par **z-score robuste** (MAD, plancher 3 %), seuils en constantes publiques. `gamedata` (types, index `made_by` / `used_in` / `teaches`, `GAME_FORMAT`), `money` (cuivre ↔ texte, rentabilité, commission HdV 5 %), `pricing` (`cheapest` : marchand ou HdV ; `sale_value` : ce que rapporte un objet ramassé, `AUCTION_CUT`), `crafting` (`craft_cost` : coût d'un objet crafté par un métier, ses composants achetés ou craftés récursivement, cycles coupés), `time` (dates locales), `merge` (points des graphiques de marché : un par jour, Scout, sinon Scout API, sinon moyenne d'Auctionator et Forever Guide ; `merge/aggregate` : moyenne par semaine ou par mois ; `merge::series` : aussi tous les relevés), `scout_api` (serveur de prix : `latest_rows` = derniers prix gardés quand ils changent + premier du jour + objets partis, `history_rows`, `ServerHouse`, `DEFAULT_SERVER`, `REFRESH_SECS`), `search` (recherche de tous les champs : chaque mot tapé dans le nom, dans n'importe quel ordre, sans casse ni accents ; ou le numéro exact), `map` (cartes, placement d'une zone sur son continent, masques), `drops` (+ `drops/records`, `drops/zone` : butin par zone, niveaux habituels = 10ᵉ / 90ᵉ centiles, valeur par kill) : fusion base Forever Guide / réel Scout, intervalle de Wilson, tri par colonne (`drops/sort` : valeurs inconnues toujours en dernier), `TRUSTED_KILLS` = 20 corps (chance réelle en vert), `format_percent` ; types partagés (`Row`, `ItemName`, `VendorPrice`, `ItemSummary`, `Snapshot`, `VendorData` / `VendorOffer`, `Theme`). `update` : comparaison de versions, binaire de la plateforme (`BINARY`), lecture du `.sha256`, `AddonInstall::offer` (addon à proposer). |
| `scout-sources` | Tout ce qui vient de l'extérieur : `import` (scripts Lua de `lua/`, intégrés par `include_str!`, exécutés par le Lua intégré `mlua`, et lecture de leur CSV), `wago` (téléchargement wago.tools) + `wago/assemble` (+ `assemble/maps`) (CSV → recettes et cartes, testé), `wowhead` (objets absents des tables du client), `price_server` (notre serveur de prix, clé `X-Scout-Key` : maisons, derniers prix, historique d'un objet), `github` (dernière Release de l'outil ou de l'addon, téléchargement vérifié par `.sha256`), `addon` (addon Scout installé : absent, lien de dev jamais touché, version du `.toc` ; installation du `Scout.zip` à côté puis renommage), `tga` (masques d'OpenMap), `wow` (dossier `_forever_` : détection Windows (lecteurs C: à Z:) ou Wine / Lutris, `export_script`, `saved_variables`, liste de Forever Guide). |
| `scout-db` | SQLite (sqlx) : `lib.rs` (`Db`, schéma, migrations), `market` (objets, favoris, relevés ; `market/scout_api` : dernier prix Scout API par objet, cache d'historique), `game` (données du jeu), `vendor` (prix et offres des marchands), `drops` (butin : base et réel ; `drops/zones` : par zone), `game/maps`, `game/wowhead`, `reference` (base de référence : export, application de ce qui est plus récent). |
| `scout-worker` | Threads de fond, un seul runtime tokio `multi_thread` (1 thread) partagé, chaque thread y fait `block_on` (son thread à lui rend la connexion SQLite au pool même quand les autres sont occupés ou en attente) : `Command` → `Event` via `mpsc` + callback `notify` (l'app y met `request_repaint`). La boucle répond aux commandes rapides ; les tâches longues (`Task` : import Scout, historique, données du jeu ; `worker/tasks`) ont chacune leur thread (`Shared::spawn`), plusieurs à la fois mais jamais deux fois la même, `Event::Busy(Task, bool)` → `State::busy(task)` grise seulement leur bouton. `Db` (une connexion, attente jusqu'à 10 min) et `Config` (`Mutex`) partagés. **Seul** endroit qui touche disque, base, réseau et processus. `config` : réglages, chemins, migration des dossiers `scout-prix` → `scout-rs`. `worker/prices` : serveur de prix (derniers prix vérifiés toutes les 10 min et téléchargés après 1 h, `Task::Prices` ; historique d'un objet sur son propre thread à chaque `LoadHistory`, puis `Event::History` à nouveau ; réglages `SetPriceServer`, maisons `Event::ServerHouses`). `worker/update` : mise à jour de l'outil (vérifiée au démarrage, jamais en build de dev ; `Command::InstallUpdate` télécharge, vérifie le SHA-256 et remplace l'exécutable par `self-replace` ; `Command::Restart` lance le nouveau puis `Event::Quit` ferme la fenêtre ; bouton dans `ui/header` ; idem pour l'addon : `Event::AddonRelease`, `Command::InstallAddon`, `widgets::addon_button` en haut et dans Réglages). `reference` : base de référence intégrée (`data/reference.db.gz`), appliquée au démarrage ; `examples/reference.rs` la régénère. Tests sur la vraie machine dans `tests/local.rs` (`#[ignore]`). |
| `app` (paquet et binaire `scout-rs`) | UI egui uniquement. `main.rs`, `app.rs` (onglets de modules, barre d'état, module courant), `state.rs` (`State` lu par l'UI : données du worker, module / vue / filtre / sélection ; `state/apply` : effet des `Event`, `state/loads` : données chargées au premier usage ; `revision` change à chaque modification des objets ou favoris, pour les caches ; `auction_price`, `buy_price`). |
| `scout-server` (binaire, hors de l'appli) | Serveur de prix du VPS (`docs/serveur.md`), indépendant des autres crates : `blizzard` (client Battle.net bloquant : jeton client credentials mis en cache, liste des maisons, enchères en GET conditionnel), `storage` (bruts `raw/AAAA/MM/JJ/…json.zst`, écriture atomique, place libre), `db` (SQLite sqlx : `houses`, `raw_snapshots`, `fetch_log` ; `db/prices` : `prices`), `aggregate` (prix d'une liste par objet : min, p25 et médiane pondérés par la quantité), `collector` (relevé périodique, contenu identique = rien d'écrit, prix écrits avec chaque nouvel instantané, rattrapage au démarrage), `api` (axum : `/health`, `/privacy`, `/v1/houses`, `/v1/houses/{id}/prices` en CSV par pages, gzip ; `api/access` : clés `SCOUT_KEYS`, limite de débit en mémoire), `main` (réglages par variables d'environnement, arrêt sur SIGTERM). Image : `Dockerfile` à la racine ; module `scout` du homelab (`~/dev/vps/modules/scout`). |

Fichiers de `app/src/ui/` : voir `docs/modules.md`.
