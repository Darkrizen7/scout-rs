# Architecture détaillée

| Crate | Rôle |
|---|---|
| `scout-core` | Données et logique **pures**, testées (ni disque, ni réseau, ni egui ; `sqlx` seulement avec la feature `sqlx`, pour `#[derive(FromRow)]`). `analysis` + `analysis/stats` : prix du jour = médiane des prix min du jour (date locale) ; week-end vs semaine par **test de permutation** (exact ou Monte-Carlo à graine fixe), effet de marché avec **les jours comme unité** ; prix du jour anormal par **z-score robuste** (MAD, plancher 3 %), seuils en constantes publiques. `gamedata` (types, index `made_by` / `used_in` / `teaches`, `GAME_FORMAT`), `money` (cuivre ↔ texte, rentabilité, commission HdV 5 %), `pricing` (`cheapest` : marchand ou HdV ; `sale_value` : ce que rapporte un objet ramassé, `AUCTION_CUT`), `crafting` (`craft_cost` : coût d'un objet crafté par un métier, ses composants achetés ou craftés récursivement, cycles coupés), `time` (dates locales), `merge` (points des graphiques de marché : un par jour, Scout sinon moyenne des deux autres sources ; `merge/aggregate` : moyenne par semaine ou par mois ; `merge::series` : aussi tous les relevés), `search` (recherche de tous les champs : chaque mot tapé dans le nom, dans n'importe quel ordre, sans casse ni accents ; ou le numéro exact), `map` (cartes, placement d'une zone sur son continent, masques), `drops` (+ `drops/records`, `drops/zone` : butin par zone, niveaux habituels = 10ᵉ / 90ᵉ centiles, valeur par kill) : fusion base Forever Guide / réel Scout, intervalle de Wilson, tri par colonne (`drops/sort` : valeurs inconnues toujours en dernier), `TRUSTED_KILLS` = 20 corps (chance réelle en vert), `format_percent` ; types partagés (`Row`, `ItemName`, `VendorPrice`, `ItemSummary`, `Snapshot`, `VendorData` / `VendorOffer`, `Theme`). |
| `scout-sources` | Tout ce qui vient de l'extérieur : `import` (scripts Lua de `lua/`, intégrés par `include_str!`, et lecture de leur CSV), `wago` (téléchargement wago.tools) + `wago/assemble` (+ `assemble/maps`) (CSV → recettes et cartes, testé), `wowhead` (objets absents des tables du client), `tga` (masques d'OpenMap), `wow` (dossier `_forever_` : détection Wine, `export_script`, `saved_variables`, liste de Forever Guide). |
| `scout-db` | SQLite (sqlx) : `lib.rs` (`Db`, schéma, migrations), `market` (objets, favoris, relevés), `game` (données du jeu), `vendor` (prix et offres des marchands), `drops` (butin : base et réel ; `drops/zones` : par zone), `game/maps`, `game/wowhead`. |
| `scout-worker` | Threads de fond, un seul runtime tokio `multi_thread` (1 thread) partagé, chaque thread y fait `block_on` (son thread à lui rend la connexion SQLite au pool même quand les autres sont occupés ou en attente) : `Command` → `Event` via `mpsc` + callback `notify` (l'app y met `request_repaint`). La boucle répond aux commandes rapides ; les tâches longues (`Task` : import Scout, historique, données du jeu ; `worker/tasks`) ont chacune leur thread (`Shared::spawn`), plusieurs à la fois mais jamais deux fois la même, `Event::Busy(Task, bool)` → `State::busy(task)` grise seulement leur bouton. `Db` (une connexion, attente jusqu'à 10 min) et `Config` (`Mutex`) partagés. **Seul** endroit qui touche disque, base, réseau et processus. `config` : réglages, chemins, migration des dossiers `scout-prix` → `scout-rs`. Tests sur la vraie machine dans `tests/local.rs` (`#[ignore]`). |
| `app` (paquet et binaire `scout-rs`) | UI egui uniquement. `main.rs`, `app.rs` (onglets de modules, barre d'état, module courant), `state.rs` (`State` lu par l'UI : données du worker, module / vue / filtre / sélection ; `state/apply` : effet des `Event`, `state/loads` : données chargées au premier usage ; `revision` change à chaque modification des objets ou favoris, pour les caches ; `auction_price`, `buy_price`). |

Fichiers de `app/src/ui/` : voir `docs/modules.md`.
